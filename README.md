# layering —— 模块依赖的分层构建计划与环

Java 17 模块分层构建计划工具，仅用 JDK 标准库（`javac` / `java`），无第三方依赖、无 Maven/Gradle。

## 怎么跑

```bash
source /c/tmp/genv.sh          # 切到 JDK 17（本机环境）
bash scripts/build.sh          # 编译 src/main -> out，src/test -> out-test，check -> out-check
bash scripts/test.sh           # 跑既有用例（12 个，手写断言 runner）
bash scripts/check.sh          # 跑固定验收程序（10 个场景）
```

CLI：

```bash
java -cp out layering.Planner --check <输入文件>          # 只校验，OK <模块数> <层数>
java -cp out layering.Planner --plan  <输入文件> [--out <文件>]   # 打印分层计划
java -cp out layering.Planner --changed A,B <输入文件>    # 打印重建集（名字升序）
```

退出码：`0` 成功；`1` 有环；`2` 参数或输入错误。

## 输入格式（固定，不允许改）

- `module <name>` 声明模块；
- `edge <from> -> <to> : api|impl` 声明依赖边（`from` 依赖 `to`）；
- 以 `#` 起头的行与空行被忽略；
- 未知模块 / 重复声明 / 非法 scope → 退出码 `2` 并打印 `error: <行号>: <信息>`，不抛栈、不静默。

## 对外契约（10 条，验收点唯一出处）

1. **解析**：按上面格式解析；任何错误一律退出码 `2` + 行号，不许抛栈、不许静默吞掉。
2. **分层**：SCC 缩点 → 拓扑层级；`layer 0` 是没有出边依赖的底层，逐层向上（最长路径到 sink）。
3. **同层排序与格式**：同层内按模块名升序（`String.compareTo`，区域无关）；输出每行 `L<层号> <模块名>`
   （SCC 内多个模块按名字升序各占一行）。
4. **确定性**：边的声明顺序打乱后输出**逐字节相同**；内部一律用 `TreeMap`/`TreeSet` 或排序后的数组，
   不许依赖 `HashMap`/`HashSet` 迭代顺序。
5. **环必须给具体路径**：有环时 `--plan` 退出码 `1`，输出形如 `CYCLE A -> B -> C -> A`；
   选取规则：**长度最短 → 起点名字典序最小 → 路径字典序最小**，用邻接按名字升序的确定性搜索求出。
6. **`--check`**：只校验不写盘；有环 `1`，参数/输入错 `2`，合法 `0`，并打印 `OK <模块数> <层数>`。
7. **`--plan [--out <file>]`**：打印计划；带 `--out` 时落盘（先写 `.tmp` 再 `rename`，
   **内容未变则不写**、保留 mtime）。
8. **增量**：`--changed A,B` 时重建集 = 变更模块 ∪ **按 `api` 传递闭包**所有（直接或间接）依赖它们的模块；
   输出按名字升序。
9. **`impl` 不参与传递**：`X --impl--> Y` 时，Y 变化**只**让 X 重建，不再往上传播到 X 的 `api` 依赖者。
10. **`impl` 参与环检测**：任何 scope 的边都计入环（`A --impl--> B --api--> A` 必须被报出来）；
    输出不含绝对路径、时间戳、主机名；不读环境变量、不读墙钟。

## 难度要点（两条互相牵制的硬约束）

- **确定性（契约 4）** 要求所有拓扑/排序基于有序容器，与输入行的物理顺序解耦。
- **impl 边的双重角色**：在「重建集传递闭包」里 impl 边只让直接依赖者重建、不向上传播
  （契约 9），否则改一个底层模块就把半个仓库拉进重建集；但在「环检测」里 impl 边又必须计入
  （契约 10），「实现回指接口」的环最容易被漏检。只能显式维护**两张图**
  （传递闭包图只含 `api`、环检测图含全部边）；且 SCC 缩点只给成员集合、会丢掉环内具体路径，
  故在缩点之外保留原图做最小环搜索。
